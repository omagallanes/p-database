## 12. Conocimiento técnico reutilizable

### Patrón 1: Verificación de endpoints de creación con D-06

**Descripción**: Los endpoints de creación de valores globales (Platform, ClientProject, UseCase, ModelHint) deben implementar:
1. Auth check como primera operación
2. Normalización de nombres (trim + uppercase o trim + lowercase)
3. Upsert por slug para garantizar unicidad

**Código de referencia** (`app/api/platforms/route.ts`):
```typescript
export async function POST(request: NextRequest) {
  try {
    const session = await auth()
    
    if (!session?.user) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
    }

    const body = await request.json()
    const data = createPlatformSchema.parse(body)

    // Normalización: trim + uppercase (D-06)
    const normalizedName = data.name.trim().toUpperCase()
    const normalizedSlug = normalizedName.toLowerCase()

    // Upsert para evitar duplicados (unicidad por slug)
    const platform = await prisma.platform.upsert({
      where: { slug: normalizedSlug },
      update: {},
      create: {
        name: normalizedName,
        slug: normalizedSlug,
      },
    })

    return NextResponse.json({ data: platform }, { status: 201 })
  } catch (error) {
    // ... error handling
  }
}
```

**Aplicabilidad**: Patrón obligatorio para TODOS los endpoints de creación de valores globales (tags, platforms, categories, clientProjects, useCases, modelHints).

### Patrón 2: Rate limiting en middleware con Upstash (documentado, no implementado)

**Descripción**: Rate limiting debe implementarse en `middleware.ts` como capa de protección global antes de llegar a las API routes (D-08).

**Código documentado** (pendiente de implementación):
```typescript
import { Ratelimit } from "@upstash/ratelimit"
import { Redis } from "@upstash/redis"

// Rate limiter: 20 requests/min por IP para POST endpoints
const ratelimit = new Ratelimit({
  redis: Redis.fromEnv(),
  limiter: Ratelimit.fixedWindow(20, "60 s"),
  analytics: true,
})

export default auth(async (req) => {
  // Rate limiting para endpoints POST de API
  if (req.method === "POST" && pathname.startsWith("/api/")) {
    const ip = req.ip ?? req.headers.get("x-forwarded-for") ?? "unknown"
    const { success, reset } = await ratelimit.limit(ip)
    
    if (!success) {
      return new NextResponse(
        JSON.stringify({ error: "Too many requests" }),
        {
          status: 429,
          headers: {
            "Retry-After": String(Math.ceil((reset - Date.now()) / 1000)),
          },
        }
      )
    }
  }

  // ... lógica de autenticación existente (NO MODIFICAR)
})
```

**Aplicabilidad**: Patrón de protección global para TODOS los endpoints POST de API. Previene abuso automatizado.

### Lección 1: Verificar antes de implementar

**Lección**: Antes de "implementar" algo, verificar si ya existe en el código base. En este Sprint, el plan asumía que los endpoints de creación debían implementarse, pero la verificación del código reveló que ya fueron creados correctamente.

**Aplicabilidad**: Siempre verificar el estado actual del repositorio antes de asumir que algo debe implementarse. Usar `glob`, `read`, y `grep` para inspeccionar código existente.
