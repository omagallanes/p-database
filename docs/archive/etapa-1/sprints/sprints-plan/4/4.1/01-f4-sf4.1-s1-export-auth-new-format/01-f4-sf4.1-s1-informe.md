**Campo `categoryId` eliminado del JSON**: El plan original mencionaba mantener `categoryId` como campo legacy, pero este campo fue eliminado del schema Prisma cuando se implementó la relación N:M `PromptCategory`. Por lo tanto, no es posible incluirlo en el JSON exportado.

## 12. Conocimiento técnico reutilizable

### Patrón 1: Auth check como PRIMERA operación en API route

**Descripción**: El auth check debe ejecutarse antes de cualquier acceso a base de datos para prevenir exposición de datos.

**Código de referencia** (`app/api/export/prompts/route.ts`):
```typescript
export async function GET(request: NextRequest) {
  try {
    // Action 1: Auth check - FIRST operation before any DB access
    const session = await auth()

    if (!session?.user?.id) {
      return NextResponse.json(
        { error: "Unauthorized" },
        { status: 401 }
      )
    }

    const userId = session.user.id
    // ... resto de la lógica (acceso a DB)
  }
}
```

**Aplicabilidad**: Patrón obligatorio para TODOS los endpoints que acceden a datos sensibles o personales. Previene exposición de datos antes de verificar permisos.

### Patrón 2: Filtrado por userId en queries multi-usuario

**Descripción**: Todas las queries que leen datos deben filtrar por `userId` del usuario autenticado para garantizar aislamiento de datos.

**Código de referencia**:
```typescript
const prompts = await prisma.prompt.findMany({
  where: {
    userId: userId,  // CRÍTICO: aislamiento de datos
  },
  include: { ... },
})
```

**Aplicabilidad**: Patrón obligatorio para endpoints que retornan datos de usuario (export, list, search, etc.).

### Patrón 3: Include anidado para relaciones N:M

**Descripción**: Para cargar relaciones N:M completas, usar include anidado: `{ relation: { include: { entity: true } } }`.

**Código de referencia**:
```typescript
include: {
  platforms: { include: { platform: true } },
  categories: { include: { category: true } },
  clientProjects: { include: { clientProject: true } },
  useCases: { include: { useCase: true } },
  modelHints: { include: { modelHint: true } },
  tags: { include: { tag: true } },
}
```

**Aplicabilidad**: Patrón estándar para cargar relaciones N:M en Prisma. Ver sección 17 de `integracion-prisma-typescript.md`.

### Patrón 4: Transformación de relaciones N:M a arrays de nombres

**Descripción**: Para exportación/serialización, transformar relaciones N:M a arrays simples de nombres.

**Código de referencia**:
```typescript
platforms: prompt.platforms.map((pp) => pp.platform.name),
categories: prompt.categories.map((pc) => pc.category.name),
clientProjects: prompt.clientProjects.map((cp) => cp.clientProject.name),
useCases: prompt.useCases.map((uc) => uc.useCase.name),
modelHints: prompt.modelHints.map((mh) => mh.modelHint.name),
tags: prompt.tags.map((pt) => pt.tag.name),
```

**Aplicabilidad**: Útil para exportación, serialización JSON, o cuando se necesitan solo los nombres (no IDs completos).

### Patrón 5: Campos legacy para compatibilidad durante transición

**Descripción**: Mantener campos legacy en el formato de exportación para permitir compatibilidad con imports antiguos.

**Código de referencia**:
```typescript
// Legacy fields (maintain for backward compatibility with old imports)
platform: prompt.platform,
clientOrProject: prompt.clientOrProject,
useCase: prompt.useCase,
modelHint: prompt.modelHint,
```

**Aplicabilidad**: Patrón crítico durante transiciones de schema donde coexisten formato antiguo y nuevo. Permite que imports antiguos sigan funcionando.

### Patrón 6: Serialización de fechas para JSON

**Descripción**: Convertir objetos `Date` a ISO strings antes de serializar a JSON.

**Código de referencia**:
```typescript
createdAt: prompt.createdAt.toISOString(),
updatedAt: prompt.updatedAt.toISOString(),
```

**Aplicabilidad**: Patrón estándar para serialización de fechas en Next.js App Router (no puede serializar Date objects automáticamente). Ver sección 21 de `conocimiento_tecnico_preventivo.md`.
