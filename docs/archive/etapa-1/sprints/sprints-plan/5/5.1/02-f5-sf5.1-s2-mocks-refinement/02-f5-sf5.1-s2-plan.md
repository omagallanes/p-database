### Acción 4: Refinar mocks de prompts-[id].test.ts (4 tests)

**Qué**: Refinar mock de $transaction para ejecutar función y retornar resultado.

**Por qué**: Mock actual no ejecuta la función passed to $transaction, causando que tests de update fallen.

**Cambios requeridos**:
```typescript
// Mock de $transaction debe:
$transaction: jest.fn(async (fn) => {
  // Crear mock de transaction object
  const mockTx = {
    prompt: {
      update: jest.fn().mockResolvedValue({ id: "prompt-1", userId: "owner-123" }),
    },
    promptTag: {
      deleteMany: jest.fn().mockResolvedValue({ count: 0 }),
      create: jest.fn().mockResolvedValue({ promptId: "prompt-1", tagId: "tag-1" }),
    },
    // ... más modelos
  }
  
  // Ejecutar función con mockTx y retornar resultado
  return await fn(mockTx)
}),
```

**Validación**: `npm test -- tests/api/prompts-[id].test.ts` — 9/9 tests pasando.

### Acción 5: Refinar mocks de PromptFilters.test.tsx (5 tests)

**Qué**: Cambiar mock de URLSearchParams de global a por instancia.

**Por qué**: Mock global no intercepta creación de nuevas instancias de URLSearchParams en el componente.

**Cambios requeridos**:
```typescript
// En lugar de mock global en jest.setup.js:
// Crear factory function para cada test
const createMockURLSearchParams = (initialParams = {}) => {
  const params = new URLSearchParams()
  Object.entries(initialParams).forEach(([key, value]) => {
    params.append(key, value)
  })
  
  return {
    getAll: (key) => params.getAll(key),
    toString: () => params.toString(),
    delete: jest.fn((key) => params.delete(key)),
    append: jest.fn((key, value) => params.append(key, value)),
    set: jest.fn((key, value) => params.set(key, value)),
  }
}

// En cada test:
const mockParams = createMockURLSearchParams({ platformIds: "plat-1" })
```

**Validación**: `npm test -- tests/components/PromptFilters.test.tsx` — 8/8 tests pasando.

### Incidencias previsibles

### Dependencias sensibles

| Dependencia | Sensibilidad | Justificación |
|-------------|-------------|---------------|
| Mocks de Prisma | CRÍTICA | Tests de API dependen completamente de mocks correctos |
| Mocks de Zod schemas | ALTA | Tests deben incluir todos los campos requeridos |
| Contexto de ViewModeProvider | MEDIA | Tests de componentes requieren contexto configurado |

### Advertencias operativas

1. **No modificar código de producción**: Este Sprint es SOLO para mocks y tests. Si se encuentran bugs reales, documentarlos pero no corregirlos.
2. **Mocks deben reflejar código real**: Revisar archivos de producción (`app/api/`, `components/`) para asegurar que mocks son fieles.
3. **Cobertura es objetivo, no obsesión**: 60% es la meta, pero lo importante es cubrir flujos críticos, no líneas individuales.
4. **SF-5.2 depende de este Sprint**: Sin SF-5.1 completada, no se puede ejecutar SF-5.2 (validación integral + deploy).
