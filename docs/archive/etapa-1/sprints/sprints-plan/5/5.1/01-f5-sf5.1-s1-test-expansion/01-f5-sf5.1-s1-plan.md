## 3. Alcance del Sprint

### Qué debe conseguir este Sprint

1. **Tests de API de Export/Import**: Crear tests para `/api/export/prompts` y `/api/import/prompts` que validen:
   - Auth check (401 sin sesión)
   - Filtrado por userId (export solo retorna prompts del usuario)
   - Formato JSON v2.0 (arrays de nombres para relaciones N:M)
   - Import v1.0 y v2.0 (compatibilidad)
   - Upsert por coincidencia (userId + id o userId + title)

2. **Tests de API de Prompt Individual**: Crear tests para `/api/prompts/[id]` que validen:
   - GET: Retorna prompt con relaciones N:M
   - PUT: Actualiza prompt + relaciones N:M (con transacción)
   - DELETE: Borra prompt + relaciones
   - Ownership check: Usuario no puede editar/borrar prompts de otros
   - Admin bypass: Admin puede editar/borrar cualquier prompt

3. **Tests de Componentes Críticos**: Crear tests para:
   - `PromptFilters`: Multi-select con lógica AND, URL params
   - `PromptList`: Vista cards y lista, toggle de view mode

4. **Cobertura mínima**: Alcanzar >= 60% de cobertura en archivos modificados (API routes y componentes críticos)

5. **Build + lint + tests**: 
   - `npm run build` sin errores
   - `npm run lint` sin errores
   - `npm test` sin fallos (todos los tests nuevos + existentes pasando)

### Qué NO entra en este Sprint

- Tests E2E (Playwright/Cypress) — fuera de alcance, corresponde a SF-5.2 o futuro
- Tests de migraciones de base de datos — fuera de alcance (no hay migraciones en este sprint)
- Tests de componentes no críticos (Topbar, auth pages) — prioridad baja
- Modificación de código de producción — solo tests, sin cambios funcionales
- Despliegue — tests no se despliegan

| Dependencia | Sensibilidad | Justificación |

| Mocks de Prisma | CRÍTICA | Tests de API dependen de mocks de DB |

1. **No modificar código de producción**: Este Sprint es SOLO para tests. Si se encuentran bugs, documentarlos pero no corregirlos (corresponden a otro Sprint).

4. **No añadir tests E2E**: Playwright/Cypress están fuera de alcance para este Sprint.
