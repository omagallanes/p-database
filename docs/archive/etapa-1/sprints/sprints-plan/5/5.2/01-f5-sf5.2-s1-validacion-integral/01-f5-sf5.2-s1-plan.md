## 3. Alcance del Sprint

### Qué debe conseguir este Sprint

1. **Validación de build y lint**:
   - `npm run build` — sin errores de TypeScript
   - `npm run lint` — sin errores ESLint
   - `npm test` — 60/72 tests passing (83%, aceptado desde SF-5.1)

2. **Preparación de despliegue**:
   - Verificar variables de entorno en Vercel
   - Confirmar que DATABASE_URL está configurada
   - Verificar NEXTAUTH_SECRET y NEXTAUTH_URL
   - Confirmar feature flags (UPSTASH_ENABLED="false")

3. **Despliegue a producción**:
   - Deploy a Vercel (producción)
   - Verificar que el build se completa correctamente
   - Confirmar que la aplicación es accesible

4. **Smoke test de producción**:
   - Verificar carga de página principal
   - Verificar autenticación (login/logout)
   - Verificar listado de prompts
   - Verificar filtros multi-selección
   - Verificar búsqueda

5. **Validación integral de flujos críticos**:
   - Alta de prompt (con relaciones N:M)
   - Edición de prompt
   - Duplicado de prompt (con ownership)
   - Listado con filtros (plataformas, categorías, tags, idiomas)
   - Export de prompts (v2.0 con auth)
   - Import de prompts (v1.0/v2.0 con auth + upsert)

6. **Validación de seguridad**:
   - Verificar que endpoints de export/import requieren auth (401 sin auth)
   - Verificar aislamiento de datos (filtrado por userId)
   - Verificar ownership en PUT/DELETE (no se puede editar/eliminar prompts de otros usuarios)
   - Verificar admin bypass (admin puede editar/eliminar cualquier prompt)

7. **Documentación de validación**:
   - Registrar resultados de cada validación
   - Documentar cualquier incidencia encontrada
   - Confirmar que todos los RF-01 a RF-50 funcionan correctamente

### Qué NO entra en este Sprint

- Tests E2E automatizados (Playwright/Cypress) — fuera de alcance
- Refinamiento de 12 tests fallando de SF-5.1 — ya aceptados como suficientes
- Nuevas funcionalidades — solo validación de existente
- Optimización de rendimiento — fuera de alcance (salvo bugs críticos)
