## 12. Conocimiento técnico reutilizable

### Patrón 1: Multi-select con badges + creación inline (REUTILIZADO)

**Contexto**: Campos multivalor con creación de nuevos valores desde el formulario.

**Solución implementada** (replicada para Client/Project, Use Case, Model Hint):
```typescript
// Estado para valores seleccionados
const [selectedClientProjects, setSelectedClientProjects] = useState<ClientProject[]>(...)

// Función toggle
const toggleClientProject = (clientProject: ClientProject) => {
  if (selectedClientProjects.find((cp) => cp.id === clientProject.id)) {
    setSelectedClientProjects(selectedClientProjects.filter((cp) => cp.id !== clientProject.id))
  } else {
    setSelectedClientProjects([...selectedClientProjects, clientProject])
  }
}

// Creación inline
const handleCreateClientProject = async () => {
  const response = await fetch('/api/client-projects', {
    method: 'POST',
    body: JSON.stringify({ name: newClientProjectName }),
  })
  const newClientProject = await response.json()
  setSelectedClientProjects([...selectedClientProjects, newClientProject])
}
```

**Reutilizado desde**: SF2.1-S1 (Platform)  
**Aplicado en**: Client/Project, Use Case, Model Hint

### Patrón 2: Endpoint con normalización y unicidad (REUTILIZADO)

**Contexto**: Creación de valores con validación de duplicados.

**Solución implementada** (replicada para los 3 endpoints):
```typescript
// Normalización
const normalizedName = data.name.trim().toUpperCase()
const normalizedSlug = normalizedName.toLowerCase()

// Upsert para unicidad
const clientProject = await prisma.clientProject.upsert({
  where: { slug: normalizedSlug },
  update: {},
  create: { name: normalizedName, slug: normalizedSlug },
})
```

**Reutilizado desde**: SF2.1-S1 (Platform)  
**Aplicado en**: ClientProject, UseCase, ModelHint

### Lección aprendida 1: Patrón reutilizable reduce tiempo de desarrollo

**Observación**: El patrón de multi-select + creación inline de SF2.1-S1 se replicó exitosamente para 3 campos adicionales en SF2.1-S2 con mínimo esfuerzo.

**Lección**: Invertir tiempo en crear patrones reutilizables bien documentados reduce significativamente el tiempo de desarrollo de features similares posteriores.

**Acción futura**: Documentar patrones en `conocimiento_tecnico_preventivo.md` inmediatamente después de validarlos.

### Lección aprendida 2: Consistencia en normalización es crítica

**Observación**: Aplicar la misma normalización (trim + uppercase) en todos los endpoints de creación previene inconsistencias de datos.

**Lección**: La consistencia en normalización debe ser una decisión arquitectónica temprana, no un ajuste posterior.

**Acción futura**: Documentar reglas de normalización en gobernanza para futuras entidades.

## 19. Selector de Idioma con Códigos ISO

**Estado:** ✅ Validado  
**Código relacionado:** `components/prompt/PromptForm.tsx`  
**Sprint:** F2-SF2.1-S2  
**Descripción:** Language field usa `<Select>` con 10 idiomas. El valor guardado en BD es el código (ej. `es`), no el nombre completo (ej. `Español`).

**Lista de Idiomas:**
| Código | Nombre Visible |
|--------|----------------|
| `en` | English |
| `es` | Español |
| `nl` | Nederlands |
| `fr` | Français |
| `de` | Deutsch |
| `pt` | Português |
| `it` | Italiano |
| `catalan/valenciano` | Català/Valencià |
| `vasco` | Euskara |
| `gallego` | Galego |

**Prevención:**
- Usar `<Select>` de shadcn/ui en lugar de input de texto
- Default: `es` (Español)
- Valores del SelectItem: códigos (se guardan en BD)
- Contenido de SelectItem: nombres completos (se muestran al usuario)

**Código de ejemplo:**
```typescript
<Select
  value={formData.language}
  onValueChange={(value) =>
    setFormData({ ...formData, language: value })
  }
>
  <SelectTrigger>
    <SelectValue />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="en">English</SelectItem>
    <SelectItem value="es">Español</SelectItem>
    <SelectItem value="nl">Nederlands</SelectItem>
    {/* ... más idiomas */}
  </SelectContent>
</Select>
```
