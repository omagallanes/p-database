## 12. Conocimiento técnico reutilizable

### Patrón 1: Serialización de fechas para componentes cliente en Next.js

**Contexto**: Prisma retorna `Date` objects pero componentes cliente necesitan strings serializados.

**Solución implementada**:
```typescript
// En página server component antes de pasar a componente cliente
const serializedPrompt = {
  ...prompt,
  createdAt: prompt.createdAt.toISOString(),
  updatedAt: prompt.updatedAt.toISOString(),
}

return <PromptForm prompt={serializedPrompt} ... />
```

**Reutilizable para**: Cualquier campo Date de Prisma que deba pasarse a componentes cliente

**Riesgo si se ignora**: Error de build: "Type 'Date' is not assignable to type 'string'"

### Patrón 2: Campos opcionales con @db.Text en Prisma

**Contexto**: Campos de texto largo opcionales que no deben tener límite de longitud.

**Solución implementada**:
```prisma
model Prompt {
  prePrompt   String?   @db.Text
  manualDeUso String?   @db.Text
}
```

**Reutilizable para**: Campos de texto largo opcionales (notas, descripciones extendidas, etc.)

**Riesgo si se ignora**: Campos String sin @db.Text tienen límite de 191 caracteres en PostgreSQL

### Patrón 3: prisma db push para desarrollo en entornos no interactivos

**Contexto**: GitHub Codespaces y otros entornos CI/CD no soportan `prisma migrate dev` (interactivo).

**Solución implementada**:
```bash
# En lugar de: prisma migrate dev --name migration_name
# Usar: prisma db push
prisma db push
```

**Reutilizable para**: Desarrollo en Codespaces, GitHub Actions, Docker, entornos no interactivos

**Nota**: `prisma db push` es para desarrollo; `prisma migrate deploy` para producción

### Lección aprendida 1: Verificar PostgreSQL antes de migraciones

**Problema**: Migración falló por DB no disponible.

**Lección**: Siempre verificar que PostgreSQL está corriendo antes de ejecutar comandos de Prisma.

**Acción preventiva**: Añadir verificación al inicio de sesiones de desarrollo:
```bash
docker-compose -f docker-compose.dev.yml up -d postgres
```

### Lección aprendida 2: Orden ABC en selectores mejora UX

**Observación**: Idiomas en orden alfabético son más fáciles de encontrar.

**Lección**: Selectores largos deben ordenarse alfabéticamente por valor o código.

**Acción futura**: Aplicar mismo patrón a otros selectores (Platform, UseCase, etc.)
