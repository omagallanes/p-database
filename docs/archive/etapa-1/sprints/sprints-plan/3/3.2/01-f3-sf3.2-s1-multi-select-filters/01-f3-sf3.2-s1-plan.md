## 3. Alcance del Sprint

### Qué debe conseguir este Sprint
1. **Platform multi-select**: Reemplazar `<Select>` simple por checkboxes con patrón `toggleTag` existente, usando `params.append()` para URL
2. **Category multi-select**: Reemplazar `<Select>` simple por checkboxes con patrón `toggleTag`, usando `params.append()` para URL
3. **Query AND para Platform**: Cambiar `where.platform = value` a `where.platforms: { every: { platformId: { in: platformIds } } }` para lógica AND

- Export/Import con auth y nuevo formato (Fase 4)
- Rate limiting (Fase 4)
- Cambios en filtros de Status, Language, Tags, Favorite (ya funcionan correctamente)

### Acción 1: Añadir `getPlatforms()` en page.tsx
**Archivo**: `app/(app)/prompts/page.tsx`

Crear función similar a `getCategories()` para fetch de platforms desde DB:

```typescript
async function getPlatforms() {
  const platforms = await prisma.platform.findMany({
    orderBy: { name: "asc" },
  })
  return platforms.map((p) => ({
    id: p.id,
    name: p.name,
    slug: p.slug,

**Cambios en where clause**:

// Platform: lógica AND con relación N:M
if (searchParams.platformIds && searchParams.platformIds.length > 0) {
  where.platforms = {
    every: {
      platformId: {
        in: searchParams.platformIds,
      },
    },
  }

// Category: lógica AND con relación N:M (ya usa categories, cambiar some→every)
if (searchParams.categoryIds && searchParams.categoryIds.length > 0) {

        in: searchParams.categoryIds,

  }

```

> **Nota**: Usar `every` en lugar de `some` para lógica AND. `every` retorna prompts que tienen TODAS las relaciones especificadas.

**Añadir `togglePlatform`** (replicar patrón `toggleTag`):
```typescript
const togglePlatform = (platformId: string) => {
  const params = new URLSearchParams(searchParams.toString())
  const currentPlatformIds = params.getAll("platformIds")
  if (currentPlatformIds.includes(platformId)) {
    params.delete("platformIds")
    currentPlatformIds
      .filter((id) => id !== platformId)
      .forEach((id) => params.append("platformIds", id))
  } else {
    params.append("platformIds", platformId)
  }
  router.push(`/prompts?${params.toString()}`)
}
```

## 7. Seguridad y no regresión

### Qué debe preservarse
- Auth check en API routes: filtros no requieren auth pero ownership se mantiene en PUT/DELETE
- Ownership: cada usuario solo ve sus propios prompts (si aplica filtrado por userId en futuro)
- Zod validation: no aplica en GET (searchParams), pero PUT/POST mantienen validación
- Datos existentes: prompts sin cambios, solo se modifica lógica de filtrado

### Qué debe revisarse
- Que `every` en Prisma funcione correctamente con relaciones N:M (verificar con test manual)
- Que URL no se vuelva excesivamente larga con muchas selecciones
- Que el patrón `toggleTag` se replique correctamente sin introducir bugs

### Riesgos de regresión
| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|-------------|---------|------------|
| `every` no funciona como esperado con N:M | MEDIA | ALTA | Verificar con test manual; fallback a `some` si es necesario |
| Filtros existentes (tags, status, etc.) se rompen | BAJA | ALTA | No modificar lógica de otros filtros; solo añadir platformIds/categoryIds |
| URL demasiado larga con muchas selecciones | BAJA | MEDIA | Limitar selecciones visibles o implementar debounce |

## 9. Riesgos o advertencias

### Incidencias previsibles
1. **`every` vs `some` en Prisma**: La lógica AND con `every` puede no comportarse como se espera con relaciones N:M. Si un prompt tiene 3 platforms y seleccionamos 2, `every` requiere que el prompt tenga TODAS las platforms seleccionadas. Verificar comportamiento exacto.
2. **Category tree**: Las categories tienen jerarquía (`parentId`). El multi-select plano puede confundir si hay padres e hijos. Se recomienda mostrar categories planas (sin indentación) como en la implementación actual.
3. **Compatibilidad con legacy `platform` field**: El schema aún tiene campo `platform String` además de relación N:M `platforms`. Asegurar que la query use la relación N:M, no el campo legacy.

### Dependencias sensibles
- **SF-1.3 completada**: Migraciones de Fase 1 aplicadas — relaciones N:M existen en DB
- **SF-3.1 completada**: PromptList ya soporta includes N:M; page.tsx ya tiene `getPlatforms()` pattern disponible
- **Patrón `toggleTag`**: Ya funciona correctamente; replicar exactamente mismo patrón

### Limitaciones
- Este Sprint no aborda optimización de rendimiento de queries AND
- No se aborda filtrado multi-selección para Status, Language, o Favorite
- Category tree se muestra plano (sin jerarquía visual)
