## 3. Alcance del Sprint

### Qué debe conseguir este Sprint
1. **Schema**: Añadir campo `promptListViewPreference String @default("cards")` al modelo `User`
2. **Migración**: Crear y aplicar migración para nuevo campo
3. **Toggle UI**: Añadir selector/toggle de vista (cards ↔ lista) en página de prompts
4. **Vista lista**: Implementar render condicional en `PromptList` con tabla que muestra: Copy, Edit, título, favorito (estrella), estado, plataformas, categorías, tags, cliente/proyecto
5. **View → Edit**: Cambiar texto del botón "View" a "Edit" en vista cards
6. **Persistencia**: Leer preferencia del usuario autenticado al cargar página; actualizar preferencia al cambiar vista
7. **Exclusiones vista lista**: NO mostrar Pre-Prompt ni Manual de uso

### Qué NO entra en este Sprint
- Filtros multi-selección con lógica AND (SF-3.2)
- Cambios en PromptForm o navegación post-guardado (Fase 2 completada)
- Export/Import con auth y nuevo formato (Fase 4)
- Preferencia de vista reutilizable en otras pantallas (fuera de alcance según Briefing §4)

## 6. Validación y pruebas

### Qué debe validarse
1. **Toggle funciona**: Click en toggle cambia entre vista cards y lista
2. **Vista lista correcta**: Muestra Copy, Edit, título, estrella, estado, plataformas, categorías, tags, cliente/proyecto
3. **Vista lista excluye**: NO muestra Pre-Prompt ni Manual de uso
4. **View → Edit**: Botón en vista cards muestra "Edit" no "View"
5. **Persistencia**: Cambiar vista, recargar página, confirmar que se recuerda la última vista
6. **Sin auth**: Usuario no autenticado ve vista por defecto (cards)

### Mecanismos existentes
- `npm run build`: Verificación de compilación Next.js
- `npm run lint`: ESLint
- `npm test`: Jest + React Testing Library

### Pruebas manuales requeridas
| Flujo | Acción | Resultado esperado |
|-------|--------|-------------------|
| Toggle | Click en toggle cards→lista | Vista cambia a tabla |
| Toggle | Click en toggle lista→cards | Vista cambia a grid |

| Auth | Sin sesión | Vista cards por defecto |

## 7. Seguridad y no regresión

### Qué debe preservarse
- Auth check en API preferences: solo usuarios autenticados pueden actualizar su preferencia
- Ownership: cada usuario solo actualiza su propia preferencia
- Zod validation: validar que `promptListViewPreference` sea "cards" o "list"
- Datos existentes: prompts sin cambios, solo se añade campo a User

### Qué debe revisarse
- Que `auth()` no falle si no hay sesión (usuario no autenticado debe ver cards por defecto)
- Que la migración no afecte datos existentes de User (campo con default seguro)

### Riesgos de regresión
| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|-------------|---------|------------|
| Vista lista no muestra datos N:M | MEDIA | ALTA | Incluir `include` de platforms, categories, clientProjects en query |
| Preferencia no persiste | BAJA | MEDIA | Verificar endpoint PATCH funciona correctamente |
| Usuario no autenticado causa error | BAJA | ALTA | Fallback a "cards" si `session?.user` es null |
| Tests existentes fallan | BAJA | MEDIA | Ejecutar `npm test` antes de commit |

## 9. Riesgos o advertencias

### Incidencias previsibles
1. **Datos N:M en PromptList**: La interface actual de `Prompt` usa `platform: string` (campo simple), pero el schema tiene relaciones N:M (`platforms: PromptPlatform[]`). La vista lista debe mostrar plataformas desde la relación N:M, no desde el campo simple.
2. **Serialización de fechas**: `page.tsx` ya transforma Date → ISO string en `getPrompts()`. Asegurar que la transformación incluya todos los campos nuevos.
3. **Auth en server component**: `auth()` debe llamarse en server component (page.tsx), no en cliente. La preferencia se lee en servidor y se pasa como prop.

### Dependencias sensibles
- **SF-1.3 completada**: Migraciones de Fase 1 aplicadas — verificadas en `04-Phases-Subphases-Plan.md`
- **SF-2.3 completada**: Navegación post-guardado implementada — no afecta este Sprint
- **API preferences**: Nuevo endpoint necesario para actualizar preferencia

### Limitaciones
- Este Sprint no aborda SF-3.2 (filtros multi-selección con lógica AND)
- La preferencia de vista es solo para listado de prompts (no reutilizable en otras pantallas — fuera de alcance)
