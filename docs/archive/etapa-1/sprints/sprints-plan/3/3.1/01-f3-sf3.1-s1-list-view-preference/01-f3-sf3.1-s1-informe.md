## 12. Conocimiento técnico reutilizable

### Patrón 1: Toggle con persistencia en Next.js App Router

**Descripción**: Componente cliente que actualiza preferencia de usuario vía API endpoint, con `useTransition` para pending state.

**Código de referencia** (`ViewToggle.tsx`):
```typescript
"use client"

export function ViewToggle({ initialViewMode }: ViewToggleProps) {
  const [viewMode, setViewMode] = useState<"cards | "list">(initialViewMode)
  const [isPending, startTransition] = useTransition()

  const handleViewChange = async (mode: "cards" | "list") => {
    startTransition(async () => {
      setViewMode(mode)
      await fetch('/api/user/preferences', {
        method: "PATCH",
        body: JSON.stringify({ promptListViewPreference: mode }),
      })
    })
  }
  // ...
}
```

**Aplicabilidad**: Reutilizable para cualquier preferencia de usuario que requiera persistencia inmediata con feedback visual.

### Patrón 2: Server Component leyendo preferencia de usuario

**Descripción**: Función asíncrona en server component que obtiene preferencia de usuario autenticado con fallback seguro.

**Código de referencia** (`page.tsx`):
```typescript
async function getUserViewPreference(): Promise<"cards" | "list"> {
  const session = await auth()
  
  if (!session?.user?.id) {
    return "cards"
  }

  const user = await prisma.user.findUnique({
    where: { id: session.user.id },
    select: { promptListViewPreference: true },
  })

  return user?.promptListViewPreference || "cards"
}
```

**Aplicabilidad**: Patrón estándar para leer cualquier preferencia de usuario en server components.

### Patrón 3: API endpoint para preferencias de usuario con Zod

**Descripción**: Route handler PATCH que valida input con Zod, verifica autenticación, y actualiza solo el usuario autenticado.

**Código de referencia** (`/api/user/preferences/route.ts`):
```typescript
const updatePreferencesSchema = z.object({
  promptListViewPreference: z.enum(["cards", "list"]),
})

export async function PATCH(request: NextRequest) {
  const session = await auth()
  if (!session?.user?.id) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 })
  }

  const body = await request.json()
  const data = updatePreferencesSchema.parse(body)

  const user = await prisma.user.update({
    where: { id: session.user.id },
    data: { promptListViewPreference: data.promptListViewPreference },
    select: { promptListViewPreference: true },
  })

  return NextResponse.json({ data: user })
}
```

**Aplicabilidad**: Patrón reutilizable para cualquier endpoint de actualización de preferencias de usuario.

### Patrón 4: Render condicional cards/lista con includes N:M

**Descripción**: `PromptList.tsx` ahora maneja ambas vistas con includes de relaciones N:M para mostrar datos completos.

**Código de referencia** (`PromptList.tsx`):
```typescript

    <Badge key={pp.platform.name}>{pp.platform.name}</Badge>
  ))
```

**Aplicabilidad**: Patrón para componentes que deben soportar legacy fields y nuevas relaciones N:M simultáneamente.
